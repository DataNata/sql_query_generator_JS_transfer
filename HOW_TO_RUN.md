# SQL Query Generator — запуск на другом компьютере

Веб-приложение: вопрос на обычном языке → ER-диаграмма, SQL-запрос и объяснение.
Написано на JavaScript (Node.js). Работает в браузере, вход по паролю.

> **Внимание:** в файле `.env` лежат пароль входа и API-ключ Groq.
> Не выкладывайте папку в открытый доступ и не отправляйте её посторонним.

---

## 1. Что нужно установить (один раз)

**Node.js версии 22 или новее** — https://nodejs.org → кнопка **LTS** → установить с настройками по умолчанию.

Проверка: откройте **PowerShell** или **Командную строку** и выполните

```
node -v
```

Должно показать `v22...` или больше. Если пишет «не является командой» — перезагрузите компьютер
после установки Node.js или установите его заново.

Больше ничего ставить не нужно: `npm install` для запуска на компьютере не требуется.

## 2. Скопировать проект

Распакуйте `sql_query_generator_JS_transfer.zip` в любую папку, например `C:\Projects\sql_query_generator`.
Путь может содержать пробелы и русские буквы.

## 3. Запустить

**Способ А — двойной щелчок:** откройте папку и дважды щёлкните **`run.bat`**.
Откроется чёрное окно сервера и браузер с адресом http://127.0.0.1:8000.

**Способ Б — из терминала:**

```
cd "C:\Projects\sql_query_generator"
node dev-server.mjs
```

и откройте в браузере http://127.0.0.1:8000.

## 4. Войти

Пароль — значение `APP_PASSWORD` в файле `.env` (откройте его Блокнотом).

После входа выберите модель (например **Groq · GPT-OSS 120B**), напишите вопрос и нажмите
**Сгенерировать** (или Ctrl + Enter). Модель **Демо-режим** работает без ключей и интернета к LLM.

## 5. Остановить

Закройте чёрное окно сервера или нажмите в нём **Ctrl + C**.
Сервер работает, только пока открыто это окно.

## Настройки (файл `.env`)

Открывается Блокнотом. После изменения — перезапустите сервер.

| Строка | Что значит |
|---|---|
| `APP_PASSWORD=...` | пароль входа (пусто — вход без пароля) |
| `SESSION_SECRET=...` | секрет для подписи входа; можно не трогать |
| `GROQ_API_KEY=...` | ключ Groq (уже вписан) |
| `OPENAI_API_KEY=`, `GEMINI_API_KEY=`, … | ключи других провайдеров — впишите, чтобы модели стали доступны |
| `PORT=8000` | порт (строку можно добавить, если 8000 занят) |
| `HOST=127.0.0.1` | `0.0.0.0` — открыть доступ с других компьютеров сети (см. ниже) |

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| `run.bat` пишет `Node.js not found` | установите Node.js (п. 1) и перезагрузите компьютер |
| В окне ошибка `EADDRINUSE` | порт 8000 занят другой программой. Добавьте в `.env` строку `PORT=8010` и откройте http://127.0.0.1:8010 |
| Открылся какой-то другой сайт на 127.0.0.1:8000 | на этом порту работает другая программа — тоже смените порт, как выше |
| Генерация пишет «Провайдер недоступен» | нет доступа в интернет к API модели. В корпоративной сети с прокси: перед запуском выполните в PowerShell `$env:HTTPS_PROXY="http://адрес-прокси:порт"; $env:NODE_USE_ENV_PROXY="1"; node dev-server.mjs` |
| «Не задан ключ…» / модель «нет ключа» | впишите ключ этой модели в `.env` и перезапустите |
| «Слишком часто…» | лимит 10 генераций в минуту — подождите минуту |
| «Вход заблокирован» | 5 неверных паролей подряд — подождите 15 минут или перезапустите сервер |

## Доступ с других компьютеров сети (по желанию)

В `.env` добавьте `HOST=0.0.0.0`, перезапустите и откройте с другого компьютера `http://<IP этого компьютера>:8000`.
Windows может спросить разрешение для Node.js в брандмауэре — разрешите для частной сети.

## Проверка, что всё цело (по желанию)

```
npm test
```

Должно закончиться строками `pass 33`, `fail 0`.

## Публикация в интернет (Netlify)

Проект готов к Netlify: пошаговая инструкция — в `README.md`, раздел «Публикация на Netlify».
Коротко: подключить папку через репозиторий или `netlify deploy --prod`, в настройках сайта задать
`APP_PASSWORD`, `SESSION_SECRET` и ключи (файл `.env` на Netlify не используется), сделать деплой.
